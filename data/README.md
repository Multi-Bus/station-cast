## 3. 정류장 단위 계산 방법

두 데이터셋 모두 `표준버스정류장ID` = `정류소번호`로 조인됩니다(실제 검증 완료: 종로2가사거리 ID `100000001`이 양쪽에서 정확히 일치). 큐 수지 모델은 **노선이 아니라 정류장 단위로 완전히 독립적**으로 계산되며, 한 정류장에 걸리는 모든 노선의 승하차를 합산합니다.

```python
stop_ts = df[df["표준버스정류장ID"] == TARGET_ID][hour_cols].sum()
```

예: 종로2가(ID `100000389`)에는 24개 노선(간선18·지선2·심야4)이 걸리며, 이걸 합산하면 7시 승차 5,629명·하차 8,251명 등 정류장 단위 실측 시계열이 나옵니다. 이 값이 `W(s,t) = W(s,t-1) + A_new(s,t) + A_transfer(s,t) - B(s,t)`의 `B(s,t)`와 하차(s,t)로 그대로 쓰입니다.

## 4. 데이터 특이사항 및 유의사항

- 결측치 0건, 음수값 0건(승하차 컬럼 전수 검사 완료)
- "몇 시에 버스가 지나가는지"는 데이터에 없고 필요하지도 않음 — 모델은 정류장 단위 시간대별 승하차 총량만 사용
- **좌표 데이터(②) 조인 결측 1,867건(원인 확인 완료)**: 데이터셋①(12,537개)과 ②(11,248행)를 조인하면 1,867개가 결측된다. 원인은 두 가지다.
  - **93.6%(1,747개)는 관할구역 불일치**: 결측 정류장ID의 지역코드 접두(앞 3자리)가 서울 주력 대역(107·121·115·113 등)과 다른 218·213·219·206·207·204 등에 몰려 있고, 실제 이름을 확인하니 `성남우체국`·`고등119안전센터`·`남한산성공원입구` 등 **경기도 성남시 지명**이었다. OA-12913은 서울 버스 노선이 경기도까지 넘어가는 구간(광역·직행버스)의 정류장도 포함하지만, 좌표 데이터(②)는 "서울특별시" 자체 등록 정류소만 다루기 때문에 관할이 다른 정류장은 애초에 그 파일에 없다.
  - **6.4%(120개)는 "가상" 차고지·기종점 정류장**: 역명에 "(가상)"이 포함된, 승객이 실제로 타고 내리지 않는 차고지/기점/종점 지점.
  - 최종 회랑 21개 정류장은 전부 서울 도심 실존 정류장이라 영향 없음(좌표 전부 매칭 확인됨).
- **표준버스정류장ID(12,537) vs ARS번호(12,364) 불일치(원인 확인 완료, 수치 정정)**: 이전에 12,435로 기록했던 ARS 유일값은 초기 분석 스크립트가 `low_memory` 옵션 없이 읽어 일부 행의 dtype이 혼용된 데이터 로딩 버그였고, 정확히는 12,364다. 실제 원인은 **하나의 ARS번호에 여러 표준버스정류장ID가 걸리는 82개 케이스**이며, 그중 대표적으로 ARS번호가 `~`(placeholder)인 정류장이 85개나 되고 이 그룹의 90.6%가 "(가상)" 차고지 정류장이었다 — 좌표 결측과 같은 원인(가상 정류장은 실제 안내번호가 없어 placeholder를 공유)이다. 표준버스정류장ID 하나가 여러 ARS번호를 갖는 반대 방향 사례는 0건. 회랑 21개 정류장에는 영향 없음.

## 5. 전처리 산출물 (B트랙 인수 대상)

원본 CSV 2종을 21개 회랑 정류장 기준으로 전처리해 `data/processed/`에 **parquet**으로 저장했다(인코딩·dtype 문제 회피, 팀 기술스택(PyArrow/DuckDB) 및 `ARCHITECTURE.md` 파이프라인과 일치). 생성 스크립트는 `src/stationcast/ingest/oa12913.py`(`run()` 함수)이며, 재실행하면 동일하게 재생성된다. B트랙은 원본 CSV 대신 이 파일을 바로 사용하면 된다.

| 파일 | 스키마 | 설명 |
|---|---|---|
| `corridor_hourly.parquet` | `표준버스정류장ID, 정류장명, 시간대(0~23), 승차, 하차` | 21개 정류장 × 24시간 = 504행. 노선 무관하게 groupby-sum 완료(long/tidy 포맷) 후 **사용년월의 일수로 나눈 일평균 값**(아래 참고). 큐 수지 방정식의 `B(s,t)`(승차)·하차(s,t) 입력값 |
| `corridor_stops.parquet` | `표준버스정류장ID, 정류장명, ARS번호, X좌표, Y좌표, 정류소 타입` | 21개 정류장 메타데이터. 계산에는 불필요하나 대시보드 표시·정류장 조회용(ARS번호는 시민이 실제 보는 5자리 안내번호) |

`data/raw/`, `data/processed/`는 `.gitignore`로 커밋되지 않는다(`.gitkeep`만 추적) — 원본·가공 데이터 파일은 각자 로컬에서 `python -m stationcast.ingest.oa12913`(또는 `run()` 호출)로 재생성해서 사용한다.

**월간 총량 → 일평균 정규화 (S2, issue #16)**: §1의 원본 컬럼은 "그 시간대의 **월간 누적** 인원"이다. 큐 수지 모델은 하루(0~23시, W가 0에서 시작해 0으로 끝남)를 가정하는데, 월간 누적값을 그대로 넣으면 W가 사용년월의 일수(6월=30일)만큼 부풀려진다. 그래서 `build_corridor_hourly`가 groupby-sum 이후 `사용년월`(YYYYMM)로 일수를 계산해 승차·하차를 그 값으로 나눈다. 이 정규화 이전 버전으로 만들어진 `corridor_wait.parquet`(S1 GATE, issue #8)는 이 부풀림 때문에 비음수 위반율 90.9%로 나왔었다.

**QA 결과**: 위 정규화를 반영한 `corridor_hourly.parquet`의 승차+하차 총합은 §"최종 확정 회랑" 표의 월간 합계(3,824,452)를 30으로 나눈 약 127,482(하루 평균)와 일치. 21개 정류장 × 24시간 = 504행 모두 존재, 결측·음수 0건. `corridor_stops.parquet`는 21개 정류장 좌표 결측 0건. 신규 모듈은 `ruff check`, `mypy`, `pytest` 전부 통과.
